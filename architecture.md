# DZ Carrier Manager — Architecture Reference

> **Module**: `dzcarriermanager`  
> **PrestaShop**: 9.1.0 (Symfony 6.4)  
> **Location**: `modules/dzcarriermanager/`  
> **Author**: Tadjedine

---

## Purpose

A native PrestaShop 9 module for managing Algerian carrier integrations (Guepex, Yalidine, ZR Express, etc.) directly from the PS back office. The seller can:

1. **View all PS orders** in a dedicated grid under Shipping → DZ Carrier Manager
2. **Confirm orders** manually before dispatching
3. **Send confirmed orders** to carrier APIs to create parcels
4. **Track parcels** as carrier status updates flow back (via webhooks — Phase 2)

The module is **self-contained** (Approach A) — all data lives in the PS database. No dependency on the Laravel API for carrier logic.

## Database Schema

Three custom tables in the PS database (prefixed with `ps_`):

### `cm_carrier_accounts`
Stores API credentials for each carrier. Seeded with a `guepex` row on install.

| Column | Type | Description |
|--------|------|-------------|
| id | INT PK | Auto-increment |
| carrier_code | VARCHAR(50) UNIQUE | e.g., `guepex`, `yalidine` |
| display_name | VARCHAR(100) | Human name |
| api_id | VARCHAR(255) | API credential |
| api_token | VARCHAR(255) | API credential |
| webhook_secret | VARCHAR(255) | HMAC-SHA256 signature verification key |
| extra_config | TEXT (JSON) | Carrier-specific config (e.g., `from_wilaya_id`, `base_url`) |
| is_default | TINYINT(1) | Default carrier for "Send to Carrier" |
| is_active | TINYINT(1) | Enabled/disabled |

### `cm_parcels`
Links PS orders to carrier parcels. Created at checkout or when confirmed.

| Column | Type | Description |
|--------|------|-------------|
| id | INT PK | Auto-increment |
| order_id | INT UNSIGNED | FK to ps_orders.id_order |
| carrier_account_id | INT | FK to cm_carrier_accounts.id |
| tracking | VARCHAR(100) | Carrier tracking number (NULL until sent) |
| import_id | BIGINT | Carrier's internal parcel ID |
| label_url | VARCHAR(500) | Shipping label PDF URL |
| delivery_type | VARCHAR(50) | `home`, `stop_desk`, etc. |
| is_economic | TINYINT(1) | Economic shipping flag |
| wilaya_name, commune_name | VARCHAR(100) | Cached address info |
| phone | VARCHAR(20) | Customer contact phone number |
| price, weight, delivery_fee | Numeric | Order/parcel financials |
| freeshipping | TINYINT(1) | Free shipping flag |
| status | VARCHAR(100) | `not_confirmed`, `confirmed`, or carrier status |

### `cm_parcel_histories`
Audit log of status changes (from webhooks and API calls).

| Column | Type | Description |
|--------|------|-------------|
| id | INT PK | Auto-increment |
| parcel_id | INT | FK to cm_parcels.id (CASCADE DELETE) |
| status | VARCHAR(100) | Status at this point in time |
| reason | TEXT | Optional context |
| raw_payload | TEXT (JSON) | Raw carrier response / event payload |
| occurred_at | DATETIME | When the status changed |

## Implementation Phases

### Phase 1 (DONE)
- Module skeleton, database, carrier abstraction
- Parcels grid with all PS orders
- Confirm + Send to Carrier (single + bulk)
- Guepex driver ported from Laravel
- Status badges, delivery type badges

### Phase 2 (DONE)
- Phone column added to Parcels grid (coalescing `cm_parcels.phone` and `ps_address.phone`)
- Option A verified for `not_confirmed` vs `confirmed` status flow
- `webhook.php` & `controllers/front/webhook.php` endpoints with CRC Challenge-Response check
- `GuepexWebhookHandler` with HMAC-SHA256 signature verification & event deduplication
- `cm_carrier_accounts.webhook_secret` column added to schema
- "My Carriers" tab (Grid, Edit form with dynamic fields, Test Connection AJAX)
- Native PS order detail integration hooks (`displayAdminOrderTabLink` & `displayAdminOrderTabContent`)

### Phase 3 (FUTURE)
- Additional carrier drivers (Yalidine, ZR Express, etc.)
- Dashboard analytics (delivery rates, returns, costs)
- Shipping label batch printing
- Export to CSV/Excel
